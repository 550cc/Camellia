# 方案决策

## 一、为什么是 A 路线（运行时指令补丁）

| 路线 | 做法 | 问题 |
|---|---|---|
| B 改 APK | 解包 libapp.so，改 isValid 返回值，重打包 | 破坏签名；桌面 OTA 后失效；MIUI 校验可能拒装 |
| **A 运行时补丁** | 注入进程，运行时 mprotect + 改写指令 | 不改文件、不动签名；换版本只需换定位 |
| C Hook JNI | Hook Java 层入口 | 目标逻辑纯 Dart AOT，无 JNI 边界可利用 |

A 路线已实测可行（v18 让「小窗」出现在长按菜单），**唯一的敌人是跨版本定位 + 补丁存活性**。

## 二、v18 的三个致命设计缺陷

### 缺陷 1：文件视图 + 硬编码偏移
```c
#define APK_ELF_OFF    0x1a1c000UL
#define TARGET_VADDR   0x19e737cUL
#define EXPECT_APK_OFF 0x340337CUL
```
- `EXPECT_APK_OFF = TARGET_VADDR + APK_ELF_OFF - 0x800000`，隐含假设 **`p_offset == p_vaddr`**（即 .text 段在文件中的偏移等于虚拟地址）
- 只要桌面 OTA 让 libapp.so 里多/少一个函数，`TARGET_VADDR` 就全错
- 而且是从 APK 文件 `pread` 出来比对，跟**运行时真实内存**是两套体系

**正确做法**：`dl_iterate_phdr` 拿 `dlpi_addr + p_vaddr / p_memsz / p_flags`，
直接得到运行时段的 [起址, 大小, 权限]，在**运行时内存**里扫描和比对。

### 缺陷 2：精确字节串匹配
305 条指令整串精确比对，score 阈值判定。
- 任何一条指令的立即数/偏移变了 → 整体不匹配
- 为覆盖 49 个版本要堆 305 条，仍然覆盖不到第 50 个版本
- 压缩到 64 条则区分度崩溃（ratio 2.6，误命中风险高）

**根因**：把「指令的语义」和「指令里的偶然常数」混为一谈。
`bl +0x1234` 和 `bl +0x5678` 是**同一种指令**，但精确匹配认为它们不同。

**正确做法**：掩码匹配（masked pattern）——
opcode 位必须精确，操作数里的立即数/偏移位**通配**。

### 缺陷 3：硬编码对象池偏移
```c
add x0, x22, #0x20   /* 0x20 = bool 字段在对象里的偏移 */
```
- 这个 0x20 只对当前 Dart 版本/类布局成立
- 桌面 OTA 换了 Dart 编译器版本，字段布局一变就废
- 这是 plan 里"字段偏移 0x20 跨版本验证"一直卡着的原因

**正确做法**：不关心字段在哪。
**跳到函数自身已有的 `return true` 块** —— 那段代码是函数自己编译出来的，
编译器已经把正确的寄存器/偏移算好了，我们只是提前跳过去。

## 三、v20 设计原则（四条铁律）

### 铁律 1：唯一性命中，否则放弃
```
matches == 1  → 打补丁
matches == 0  → 版本不支持，安全降级（保持原样）
matches >= 2  → 有歧义，放弃（禁止猜第一个）
```
这是 fail-closed。宁可这个版本没有小窗，也不能打错地方导致桌面崩溃。

### 铁律 2：命中必须落在可执行段内
命中地址 + 补丁长度必须完整落在 `PF_X` 段内，且不跨段。
防止在数据段里偶然出现的字节序列被误认为代码。

### 铁律 3：运行时视图优先
一律通过 `dl_iterate_phdr` / `/proc/self/maps` 拿**运行时**段信息，
不假设文件偏移与虚拟地址的关系。

### 铁律 4：补丁必须防回滚
patch 前把目标页登记为"受保护"，并 hook `madvise`，
拦截 `MADV_DONTNEED` 对受保护页的丢弃请求。
否则 XYRE 内存清理会把补丁静默清掉（v18 就是这样"消失"的）。

## 四、待确认/风险

- `operand_mask` 的自动推导：ARM64 指令编码需要按类别判断哪些位是操作数
- return-true 块的识别：需要扫描函数体找 `mov w0,#1; ret` 或 `mov x0,#1; ret`
  - 风险：函数可能有多个退出点，需保证选中的是"返回 true"那个
  - 备选：如果找不到干净的 return 块，退回"改条件跳转"（把 `b.ne` 改成 `b` / `nop`）
- madvise guard 在裸 syscall 环境下的实现：不能直接 `dlsym("madvise")`（我们没链 libc），
  需要从 GOT 表定位或直接 inline patch libc 的 madvise
- 本文件的假设都需要在 `03-改造设计.md` 里逐条落实并标注验证状态
