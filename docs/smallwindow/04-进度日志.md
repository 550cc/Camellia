## 2026-11-08 · 阶段：跨版本定位方案从"版本表"改为"数据驱动掩码"

### 背景
计划中「提炼跨版本稳定的字节锚/版本表」一步此前卡在模板长度的取舍上：
- N=64 → ratio≈2.6（不可用）
- N=128 → ratio 4.3–4.9（风险高）
- N=305 → ratio>10（可用但笨重，且需堆样本）
思路一直在「截短精确串换通用性」和「保留长模板换区分度」之间摇摆。

### 关键结论

1. **不需要 ARM64 语义 operand mask**。`01-方案决策.md` 第四节列的第 1 条风险项作废：
   直接对 49 个版本逐位做 `XOR/OR` 统计即可得到掩码，零语义规则、零假设、且实测 85% 信息保留。
2. **不需要版本表**。256 条掩码模板（2 KB 数据）覆盖全部 49 个 8.01 版本。
3. **适配新版本 = 重跑一次脚本**（把新 APK 丢进样本目录 → collect_all.py → derive_mask.py），
   无需改一行 C 代码。这是相对 v18 硬编码的根本性改进。
4. 「12 字节序言唯一」的猜想**已证伪**（~2000 处命中），必须用长模板 + 唯一性校验。

## 2026-11-13 09:5x 重大发现：A 侧补丁"完全无效"的真因是模块从未进入桌面进程

- probe.txt 中 **零条 com.miui.home**（只有 system / securitycenter / mishare.connectivity），桌面 maps 无 libhomeprobe.so
- LSPosed modules 日志中 Camellia 从未出现在 com.miui.home；同机 hk.uwu.reareye 对桌面有正常日志 → 非 LSPosed 全局限制
- LSPosed DB scope 中 com.hyper.Camellia 已含 com.miui.home（6 条），CamelliaLab(enabled=0) 另有 1 条
- 时间线排除"进程早于安装"：模块 08:54 装、桌面 09:02 起（仍然没注入）；am force-stop 桌面重启后（09:53, pid=22435, uid=10146）仍无注入
- 结论：**LSPosed 作用域缓存由 system_server 侧 LSPosedService 持有，DB 后改的 scope 行不刷新**，重启目标 app 无效，必须 setprop ctl.restart zygote
- 踩坑记录：lspctl 仅 status/stop；`lspctl stop` + `sh service.sh` 重启 daemon 后 system_server 变 "not connected"、Modules 0，不可用于刷新作用域，且迫使必须重启 zygote 才能恢复
- 因此此前所有"A 侧补丁写入成功但 UI 无变化"的现象，第一层原因不是补丁没命中，而是补丁代码根本没在桌面进程执行
